# Almost — Teacher Studio

Implementation starts under AL-51 / MOD07. Related planning IDs: AUTH07,
MOD03–MOD06, ANA01–ANA05. These references do not automatically mark Jira tasks done.

## Scope
Teachers create complete drafts, preview the challenge, publish to the
shared museum, archive published exhibits, and view anonymous aggregate results.
There are no classes or student-submission review queues in this demo scope.
Teachers see and change only their own exhibits. Registration offers Student and Teacher and stores the selected role. Anyone can choose Teacher in this demo; no verification is performed.

## Content and lifecycle
- A draft requires a room, display number, topic, title, original question,
  intentionally incorrect solution, 2–6 diagnostic choices, exactly one correct
  choice, and a reveal containing the corrected solution and explanation.
- Display numbers are labels, not unique identifiers. Slugs are generated by the server.
- Draft -> Published -> Archived. Published and archived content cannot be edited.
  For a correction, create a new exhibit; do not modify published data in Atlas.
- Revision checks reject a stale save/publish/archive rather than overwrite newer work.
- Existing seeded exhibits have no owner. They remain public but do not appear in
  any teacher's studio. The provisioning script never claims or changes them.
- Archiving removes discovery and new submissions. Historical attempt records
  and teacher statistics remain stored. The current student page does not provide
  an archived-history UI; that is a separate feature.

## Statistics
For the exhibit's current version, each user's stored first attempt counts once.
The existing unique Attempt index enforces this. Practice retries are not included.
Exhibit-owner attempts are excluded. Dashboard distinct learners are deduplicated
across exhibits; total attempts can be larger than distinct learners. Accuracy is
correct first attempts / all first attempts, rounded to a whole percentage.
No attempts returns null accuracy (displayed as a dash), not zero percent.
The summary includes archived exhibits. Per-exhibit breakdown uses the same version.
No names, email addresses, user IDs or free-text reasoning are sent by analytics APIs.

## API
All /api/teacher endpoints require an authenticated teacher and are no-store.
Writes require the existing APP_URL origin and X-Almost-Request header.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | /api/teacher/exhibits?page=1 | Own exhibits, 20 per page |
| GET | /api/teacher/summary | Own aggregate statistics |
| POST | /api/teacher/exhibits | Create a complete draft |
| GET | /api/teacher/exhibits/:slug | Own content, including answer and revision |
| PUT | /api/teacher/exhibits/:slug | Save a draft with expected revision |
| POST | /api/teacher/exhibits/:slug/publish | Publish with expected revision |
| POST | /api/teacher/exhibits/:slug/archive | Archive with expected revision |
| GET | /api/teacher/exhibits/:slug/stats | Anonymous answer distribution |

## Account setup
Open `/register`, select Student or Teacher and submit the form. The server accepts
only these two role strings, stores the role on User, and returns an authenticated
session. Teachers go directly to `/teacher`; students go to `/museum`. The login
page also redirects according to the stored role. Existing accounts retain their
stored role. The older command-line provisioning script is no longer required.

For a public launch, teacher identity would require verification or an invitation
before granting teacher access. The demo deliberately allows open self-selection.

## Verification
From the repository root:

    node --test apps/api/tests/teacher.test.js
    npm run build

The API tests use model doubles, not Atlas. They check role/owner boundaries,
origin rejection, content validation, lifecycle/revision guards and per-exhibit
aggregate response shape. Real MongoDB aggregation, index behavior, browser layout,
and actual deployment must still be checked against your running application.

Manual acceptance:
1. Register a teacher by selecting Teacher, then open Teacher Studio. Verify a Student selection opens the museum.
2. Save a draft; reload and verify persistence. It must not appear in Museum.
3. Edit and save; preview shows choices without revealing the correct one.
4. Publish; the exhibit appears in the selected room. Content is read-only.
5. In a separate browser/private window, log in as a student and answer.
6. Refresh results as teacher: 1 learner, 1 attempt, correct percentage/distribution.
7. Use a second student to verify distribution. Reload the first student's result;
   counts must not increase.
8. Another teacher cannot fetch or change the first teacher's exhibit by URL.
9. Archive; it leaves the gallery while teacher statistics remain available.
10. Test mobile layout, keyboard controls, empty states and error recovery.

Review the actual educational content manually before the demonstration (MOD08).
The editor warns for unsaved browser unloads and clicked links; SPA browser-history
back navigation is not blocked. Save drafts before using browser Back.
